# 2026-11-01 图鉴、变异宝典与藏品

用户开启钻石藏品礼包后获得“桃米”700005 ×1。激活与升星共用 `CollectionService.UpgradeCollection`：分类 1、藏品 700005 的首次请求成功返回 1 星、总评分 600；一次重复升星因材料不足被网关拒绝，不能当作成功或自动重发。下一星所需为重复藏品 2 份及金币 3000000，与配置、后台读视图和官方界面一致。

400 分奖励通过 `ClaimCollectionReward` 确认已领取，回包总评分 600、已领最高评分 400，无实物奖励；当前加成为“1%概率节省10%肥料”。后台评分及升星成本的现有读取逻辑与实机一致。补齐激活、升星、评分领取的协议定义，图鉴页面继续保持只读；本次没有新增自动激活或升星操作。

随后金豆豆藏品礼包开出“棉芽”700001 ×1，所属系列为果冻花园 2002、品质稀有。激活回包确认 1 星、重复持有数从 1 变为 0、总评分从 600 升至 1200；1000 分档位也已领取，后台读取视图与回包一致。它来自礼包，不作为种植藏品变异的实测样本。

## 藏品变异识别

官方 `MutantEffect` 的藏品变异为 18、奶茶为 17，但两者的图标配置均指向 `naicha`。土地卡片不再使用 18 的奶茶占位图片。补齐 `MutantInfo.collection_series_id`（field 7）和 `collection_item_id`（field 8），同时读取生长阶段和 `PlantInfo` field 41 的变异记录；后者保留既有 `extended_mutations` 字段名。

土地读取视图在藏品变异的 `mutantEffects` 项中增加 `collections`，按系列、物品 ID 去重，提供具体藏品名称和已有物品图片。只收到变异 18、未收到具体 ID 时使用通用藏品图标，不推断某款藏品，也不把变异标记当作已入库或已激活。官方编码器构造样本的解析及卡片渲染回归通过，真实藏品变异样本仍需另外核对。

官方规则明确仅蓝晶土地参与藏品变异，各档位的保底进度独立累计。稀有、珍品、天工的公开概率均为 3.33%、对应保底 40 次，不能把全农场或不同档位的收获次数合并计算。自动控制的日常农场新增“自动收获天工作物”，默认开启，兼容旧账号；关闭后自动巡田及施肥后的收获跳过天工，手动一键收获保留，游戏客户端本地开关不随之修改。

## 页面与数据

图鉴从个人页移至独立侧栏入口 `/illustrated`，包含作物图鉴、超变图鉴、藏品、变异宝典。手机侧栏使用相同菜单。作物、超变原有的购买、领取及账号隔离逻辑保留。

变异宝典分常规、装扮、藏品三类，读取官方变异配置、概率公示与系列资料，不需要运行账号。隐藏事件不作为普通变异展示；宝典的藏品系列按官方 `display` 规则筛选，珍藏室保留完整的五个系列、30 款藏品。

系列问号支持悬停查看及点击固定说明，键盘聚焦和手机点击也可使用。概率来自 `CollectionGroup.public_probability / 100`，按官方界面保留一位小数，保底次数取 `display_guarantee`。例如普通系列 4 / 8 / 12 / 24 小时的展示概率为 1.2% / 2.3% / 3.3% / 6.5%，保底分别为 120 / 60 / 40 / 20 次；该概率是系列变异概率，不表示单款藏品概率。

藏品通过 `gamepb.collectionpb.CollectionService.GetCollections` 读取蓝晶类别 `1`。请求、响应字段及字节与官方编码器和实际抓包核对；服务端未返回类别时保留错误，不把未知状态显示为空收藏。

显示系列、星级、重复持有数、展示状态、许愿状态、评分、奖励档位及激活／下一级所需材料。拥有副本不等于激活；当前评分使用服务端结果，已生效增益以 `claimed_reward_score` 为准，不把尚未领取的评分增益提前应用。

11 月 3 日进一步验证：一次打开 50 个金豆豆藏品礼包，实际获得棉芽、布丁各 1 个；两次激活各消耗 1 个副本，评分依次为 600、1200。`SwitchSceneDisplay` 的 `display_slot` 字段为 field 1，藏品使用 slot 1；`item_id=0` 取消展示，切换另一藏品会替换原藏品。一次 `ClaimCollectionReward` 同时领取 400 和 1000 分两档，状态以回包为准。

图鉴 → 藏品提供激活、升星、评分领奖、展示与取消展示。激活／升星先确认当前星级和消耗，再读取最新副本与金币余额；成功回包核对星级、副本、评分及金币变化，结果未知不自动重发。许愿及切换展台仍未开放。背包支持使用藏品礼包，礼包 toast 展示实际回包奖励名称和数量；同气连枝等普通礼包沿用同一反馈。

## 验证边界

真实账号数据不作为测试输入，回归在忽略目录的独立工作区执行。浏览器预览仅使用模拟账号、收藏数据和只读接口。账号切换、停止账号或离开页面时，旧请求结果失效，失败状态可重试读取。原始抓包、解包代码、预览与测试产物不进入发布内容。

最终受影响的后端回归 36 项、前端回归 64 项通过；核心及客户端编译、前端类型检查、构建和修改文件 lint 通过。浏览器核对了分类、筛选、搜索、详情、评分奖励、悬停／点击说明、深色主题及 320 / 390 px 手机布局。真实数据目录 16 个 JSON 文件与本轮开始时的 SHA-256 一致。

官方抓包与离线字节一致不等于长期在线验证，Node 宿主现有 ACEVM 能力限制保留。
